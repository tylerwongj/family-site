# Family Site

Tyler's small website for **family and friends** (not the public): downloads of his apps and plain-language AI tips. Launcher tile **Family Site** (Sites). Local preview http://localhost:6790 (spare ports 6791-6799, `shared-ai-context/PORTS.md`).

- **What it is:** plain static files in `site/` (HTML, one CSS, small ES-module JS, no build step, no framework). `server.mjs` is only the local preview; it is never published.
- **Live since 2026-10-14 (Tyler's yes):** GitHub Pages from the public repo `tylerwongj/family-site` → https://tylerwongj.github.io/family-site/. `.github/workflows/pages.yml` runs `npm test`, then publishes `site/` on every push to main, so **a push to main is a live change**: push tested work only. Commits use `tylerwongj@users.noreply.github.com` (repo-local git config).
- **Look:** Tyler likes the current look (2026-10-14: "I like the website as a whole"); the old mockup pick (`mockups/look-*.png`) is closed. A full restyle still starts with numbered picture mockups.
- **Audience:** non-technical family. Few words, many visuals, plain names, every step says exactly what to click. Dark by default (footer button = light), phone-first (375x812, 844x390, 891x309).
- **Tyler's taste (2026-10-14):** fewer words, more real pictures. **Only clickable things look clickable:** links/cards get a border, shadow and hover lift; buttons are filled; plain facts are icon + words with no box (`.facts`); info boxes are flat (no border); `.kbd` is only for real keyboard keys; UI words in steps are plain quoted text, never chips. **Home = apps only (Tyler 2026-10-14, 2nd round):** the app cards, then ONE link at the very bottom, "Want to learn how to improve your life with AI?", to the AI tips page. Example chats and tips live only on the AI tips page (test enforces). **Show, don't tell:** an example that mentions a photo shows the photo (test enforces; sample photos drawn with ChatGPT Images, prompts in `mockups/prompts/`); the app card shows "You say it → It types it" with the same sentence on both sides. Coloured icon tiles (`.tile c-*`) on headings and cards. Tip lines stay under ~10 words. Example order: Write a hard message, Plan dinner with what you have, Explain a confusing letter. **Questions, not labels (Tyler 2026-10-14, 3rd round):** on the AI tips page every heading and tip title is a question ("What are some ways you can use AI?", "Ever wish you could tell your computer what to do, and it just does it?", "Wonder what to type?"); the "do the clicking" guide lives on that page (old computer-use/ address forwards there). The home AI link is quiet text, not a button. Speech Transcriber shows "Works in any app" with real app logos. Every guide opens with what it's for before how. **Never read like an ad or newsletter for ChatGPT:** say "AI", no "try ChatGPT free" banners; ChatGPT is named only where a guide needs it. Few words up top. Prices are stated plainly ("ChatGPT Plus: $20 a month").

## Rules (security and trust)

- **Static only:** no server, no forms, no data collection, no analytics, no cookies, no tokens or keys in any file. Every page has the same CSP meta (scripts/styles from the site only; the only outside call is `api.github.com`), `referrer: no-referrer`, `robots: noindex` and `robots.txt` Disallow. No inline scripts/styles/handlers (CSP blocks them). `npm test` enforces all of this, plus an allowlist of outside links (`EXTERNAL_OK` in `test/site.test.mjs`).
- **Never put installers, speech models or big files in this repo.** Installers live in GitHub Releases of the public repo `tylerwongj/speech-transcriber-downloads` (made by the Speech Transcriber chat, `C:/Users/tyler/p/speech-transcriber`). The site only links to them.
- **Guides link only to official pages** (OpenAI: chatgpt.com/download, learn.chatgpt.com/docs/...). Never bundle, mirror or auto-configure someone else's software. Re-check the computer-use steps against https://learn.chatgpt.com/docs/computer-use when touching them (last checked 2026-10-14). No block of official-doc links on the page (Tyler: too many words); the download link lives in step 1. Computer-use asks are plain requests, no "@Computer" (Tyler tested 2026-10-14: in Work mode ChatGPT just does it); never mention @Computer.
- **App logos are the apps' real coloured logos** (Tyler 2026-10-14: no look-alike icons for brands), on soft tiles (dark grey in dark mode, white in light mode; the black ChatGPT logo is inverted in dark mode; Tyler: white tiles looked bad in dark mode), in `site/assets/img/apps/` from free packs (sources in its `SOURCES.txt`; Iconify JSON packs via `npm pack @iconify-json/<pack>`). Everything that isn't a brand stays Phosphor duotone. A tip that mentions a picture shows one (`img` in tips.json).
- **Never fake OS dialogs.** Install pictures are pending placeholders until real screenshots exist (below).

## Speech Transcriber downloads

- **What's new** (Tyler 2026-10-14): every public release adds an entry at the top of `#whats-new` in `site/speech-transcriber/index.html`: version, date, 1-4 lines in plain words about what people notice ("Talk while you play games"), never internal details.
- `site/assets/release.js` asks `https://api.github.com/repos/tylerwongj/speech-transcriber-downloads/releases/latest` (public, CORS-enabled, 60 checks/hour per visitor, cached 10 min in the browser). **Why not `speech-transcriber-latest.json`:** GitHub release files send no CORS header, so a web page can't read them (checked 2026-10-12 with curl). The API gives the same file names, sizes and SHA-256 (`digest`).
- Files are matched by name, same as `PLATFORMS` in `speech-transcriber/tools/release_manifest.py`: `SpeechTranscriber-Setup-<ver>.exe` (Windows), `SpeechTranscriber-<ver>-macos-arm64.dmg` (Mac); version from the tag (`speech-transcriber-v<ver>`). Only `https://github.com/tylerwongj/speech-transcriber-downloads/releases/download/...` links are ever used. From 0.3.34 a release may also carry `SpeechTranscriber-Setup-<ver>-nvidia.exe` (CUDA build, ~1.2 GB): shown only when present, as a small "Have an NVIDIA graphics card? Faster version" link under the Windows button (Tyler 2026-10-14, via the Speech Transcriber chat). **If the release file names change, update `PLATFORMS` in release.js and its test.**
- States: no release yet (GitHub 404) → "Coming soon"; GitHub unreachable → buttons open the releases page; ready → buttons, size, version, date, fingerprints. Drafts and pre-releases never show (GitHub's "latest" skips them).
- `?demo` on localhost shows clearly labelled sample data, for previewing the finished look.

## App pictures

`site/assets/img/speech-transcriber/bubble-*.png` are the app's real bubble (recording, transcribing, typed), rendered by the app's own code at 2x (offscreen PySide6, `RecordingPill.show_status`, waited ~1.5 s so the label and tick finish animating, then cropped to the picture). Re-render them when the bubble's look changes. Install steps are text only: no placeholder pictures, and never drawn copies of Windows/Mac dialogs; a real screenshot (PNG/WebP, under 300 KB, no personal info) may be added under a step later. **Screenshot quality (Tyler 2026-10-16: a blurry phone photo with the cursor over "Move to Trash" looked "extremely bad"):** a crisp original screen capture (Mac: Cmd+Shift+4 then Space; Windows: Win+Shift+S), at least 2x the shown width, never enlarged, no cursor over a button, labelled "Real screenshot"; look at it full size before publishing. `npm run shots` fails a picture with fewer pixels than 1.5x its shown width (it can't see enlarging).

## Adding things

- **AI tips / videos:** edit `site/data/tips.json` (format in its `_help`). Tips show only on the AI tips page; the Videos section stays hidden until a video exists. New icon? Add its Phosphor name to `tools/build-icons.mjs`, rerun it (source: `people-map/node_modules/@phosphor-icons/web/src/duotone/selection.json`), commit `site/assets/icons.svg`.
- **A new app:** copy `site/speech-transcriber/` to `site/<app>/`, add its card to the Apps grid in `site/index.html`, extend the expected-pages list in `test/site.test.mjs`. Its installers go in that app's own public downloads repo, never here.
- **Paths are relative** (`../assets/...`) so the site works at `/family-site/` on Pages and `/` locally. `site/404.html` is self-contained and links to `/family-site/` (change it if the repo is renamed).
